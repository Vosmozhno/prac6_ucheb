# Практическая работа №3. Формы, валидация и связанные сущности

Цель: добавить к проекту ПР2 формы создания и изменения, реализовать пять сущностей со связями и сохранить данные между перезагрузками браузера.

## Ход работы и файлы для снимков кода

1. Подключаем shared_preferences и добавляем сериализацию моделей. Методы toJson и fromJson обрабатывают отсутствующие, null и ошибочные значения без исключений на уровне отдельных полей.
   Файлы: pubspec.yaml; lib/models/book.dart; lib/models/json_values.dart. Остальные модели используют тот же подход.
2. Добавляем модели Genre, Publisher, Reader и вложенную LibraryCard. В книгах храним идентификатор издательства и списки идентификаторов авторов и жанров.
   Файлы: lib/models/genre.dart; lib/models/publisher.dart; lib/models/reader.dart.
3. Создаём единое хранилище каталога с версией формата. После изменения сначала сохраняем JSON, затем обновляем состояние приложения; при повреждении оставляем резервную копию и выводим сообщение.
   Файл: lib/repositories/library_database.dart.
4. Расширяем репозитории полным CRUD для всех пяти разделов. Сохраняем поиск, фильтры, сортировку, пагинацию и операции удаления из ПР2.
   Файл: lib/repositories/reference_repositories.dart. Общая реализация операций: lib/repositories/in_memory_repository.dart.
5. Выносим типовые проверки в общий класс Validators. Отдельно проверяем уникальность ISBN, почты, номера билета и корректность связанных записей.
   Файлы: lib/validation/validators.dart; lib/validation/entity_validation.dart.
6. Описываем поля каждой сущности списком и создаём общую форму. Один экран используется для создания и изменения, а при редактировании контроллеры заполняются загруженными данными.
   Файлы: lib/models/form_schema.dart; lib/screens/entity_form_screen.dart.
7. Добавляем выпадающий список издательств, FilterChip для авторов и жанров и вложенную группу полей билета. Значения связей получаем из актуального каталога; смена издательства сужает выбор.
   Файлы: lib/screens/entity_form_screen.dart, метод _field; lib/state/catalog_references.dart.
8. Реализуем состояние формы и проверку несохранённых изменений. PopScope и onExit показывают диалог перед выходом, пользователь может продолжить редактирование или отказаться от черновика.
   Файлы: lib/state/entity_form_notifier.dart; lib/state/unsaved_changes_guard.dart; lib/router.dart.
9. Добавляем новые разделы в навигацию и используем общие списки и карточки. Для каждой сущности доступны поиск, фильтр, сортировка, страницы и действия с записью.
   Файлы: lib/screens/reference_list_screen.dart; lib/screens/reference_detail_screen.dart; lib/widgets/library_scaffold.dart.
10. Проверяем приложение анализатором, автоматическими тестами и в браузере. Демонстрируем ошибки полей, защиту связей и восстановление сохранённой книги после обновления страницы.
    Снимки результата приведены ниже.

Служебные интерфейсы, вспомогательные модели и каждый однотипный файл отдельно в кратком отчёте описывать не требуется. В таблицах ниже перечислены все данные и правила.

## Логическая схема

~~~mermaid
erDiagram
    Publisher ||--o{ Book : издаёт
    Book }o--|{ Author : имеет_авторов
    Book }o--|{ Genre : имеет_жанры
    Reader ||--|| LibraryCard : владеет
~~~

Книга относится к одному издательству и имеет не менее одного автора и жанра. Автор, жанр и издательство могут существовать без книг. Читатель имеет ровно один билет; билет принадлежит одному читателю.

## Физическая схема

Используется localStorage через shared_preferences. Каталог хранится одной JSON-строкой, а связи — идентификаторами и вложенным объектом. SQL-таблицы в ПР3 не создаются.

~~~mermaid
flowchart TD
    S[localStorage браузера] --> K[Ключ library_catalog_v2]
    K --> V[JSON-объект: schemaVersion = 2]
    V --> B[books: массив Book]
    V --> A[authors: массив Author]
    V --> G[genres: массив Genre]
    V --> P[publishers: массив Publisher]
    V --> R[readers: массив Reader]
    B --> BI[publisherId: int; authorIds и genreIds: int arrays]
    R --> C[card: вложенный объект LibraryCard]
~~~

Корневой объект содержит поля schemaVersion, books, authors, genres, publishers, readers. Идентификаторы положительны и уникальны внутри своего массива. Связь читатель–билет дополнительно проверяется по уникальному card.id.

Пример структуры записи книги и читателя (сокращённый каталог):

~~~json
{
  "schemaVersion": 2,
  "books": [{
    "id": 21,
    "title": "Учебная книга ПР3",
    "isbn": "9780000000001",
    "year": 2026,
    "pages": 320,
    "publisherId": 3,
    "authorIds": [2],
    "genreIds": [1, 3],
    "copiesTotal": 1,
    "copiesAvailable": 1,
    "createdAt": "2026-10-22T12:00:00.000Z",
    "deletedAt": null
  }],
  "authors": [{"id": 2, "fullName": "Достоевский Ф. М.", "birthYear": 1821, "country": "Россия", "deletedAt": null}],
  "genres": [{"id": 1, "name": "Роман", "description": "", "deletedAt": null}, {"id": 3, "name": "Классика", "description": "", "deletedAt": null}],
  "publishers": [{"id": 3, "name": "Азбука", "city": "Санкт-Петербург", "foundedYear": 1995, "deletedAt": null}],
  "readers": [{
    "id": 13,
    "fullName": "Тестовый читатель ПР3",
    "email": "practice3@example.test",
    "phone": "+7 900 123 4567",
    "card": {"id": 13, "number": "RC-000013", "issuedAt": "2026-10-22T00:00:00.000Z", "expiresAt": "2027-10-22T00:00:00.000Z"},
    "deletedAt": null
  }]
}
~~~

Даты сохраняются строками ISO 8601 в UTC, отсутствие даты — null. authorIds и genreIds заменяют таблицы связей многие ко многим; card вложен в Reader. Проверки ссылок выполняются в коде приложения перед записью.

## Словарь данных

В колонке «тип» указан тип Dart. В JSON int записывается числом, List<int> — массивом чисел, DateTime — строкой ISO 8601.

| Сущность | Поле | Тип | Назначение |
|---|---|---|---|
| Все пять сущностей | id | int | Идентификатор записи, назначается репозиторием |
| Все пять сущностей | deletedAt | DateTime? | Время логического удаления; null для действующей записи |
| Book | title | String | Название книги |
| Book | isbn | String | Международный номер книги |
| Book | year | int | Год издания |
| Book | pages | int | Число страниц |
| Book | publisherId | int | Ссылка на Publisher.id |
| Book | authorIds | List<int> | Ссылки на Author.id |
| Book | genreIds | List<int> | Ссылки на Genre.id |
| Book | copiesTotal | int | Общее количество экземпляров |
| Book | copiesAvailable | int | Количество доступных экземпляров |
| Book | createdAt | DateTime? | Дата создания записи; у старых данных может отсутствовать |
| Author | fullName | String | ФИО автора |
| Author | birthYear | int | Год рождения |
| Author | country | String | Страна автора |
| Genre | name | String | Название жанра |
| Genre | description | String | Необязательное описание |
| Publisher | name | String | Название издательства |
| Publisher | city | String | Город |
| Publisher | foundedYear | int | Год основания |
| Reader | fullName | String | ФИО читателя |
| Reader | email | String | Электронная почта |
| Reader | phone | String | Телефон |
| Reader | card | LibraryCard | Единственный билет читателя |

| LibraryCard | number | String | Уникальный номер билета |

Nullable даты в моделях позволяют безопасно прочитать неполные внешние данные. В форме отсутствующие обязательные даты необходимо заполнить.

## Таблица реализованных проверок

Текстовые значения очищаются от пробелов по краям. Числовые поля принимают целые числа. Все ошибки редактируемых полей показываются под соответствующим полем.

| Сущность | Поле | Проверка |
|---|---|---|
| Все пять сущностей | id | Положительный, без повторений внутри раздела; не редактируется вручную |
| Все пять сущностей | deletedAt | Дата ISO 8601 или null; назначается операциями удаления/восстановления |
| Book | title | Обязательное, 1–200 символов |
| Book | isbn | Обязательное, до 25 символов ввода; после удаления пробелов и дефисов 13 цифр либо 9 цифр и цифра/X; уникальность без учёта разделителей и регистра X |
| Book | year | Целое от 1 до текущего года |
| Book | pages | Целое от 1 до 100000 |
| Book | publisherId | Выбрано существующее действующее издательство |
| Book | authorIds | Не менее одного существующего действующего автора |
| Book | genreIds | Не менее одного существующего действующего жанра |
| Book | copiesTotal | Целое от 1 до 100000; не меньше уже выданного количества |
| Book | copiesAvailable | Вычисляется как copiesTotal минус уже выданное количество; значение от 0 до copiesTotal |
| Book | createdAt | Устанавливается при создании; при чтении некорректная/отсутствующая дата становится null |
| Author | fullName | Обязательное, 2–150 символов |
| Author | birthYear | Целое от 1 до текущего года |
| Author | country | Обязательное, 2–80 символов |
| Genre | name | Обязательное, 2–80 символов, уникальность без учёта регистра |
| Genre | description | Необязательное, до 500 символов |
| Publisher | name | Обязательное, 2–120 символов, уникальность без учёта регистра |
| Publisher | city | Обязательное, 2–100 символов |
| Publisher | foundedYear | Целое от 1 до текущего года |
| Reader | fullName | Обязательное, 2–150 символов |
| Reader | email | Обязательное, до 254 символов, формат адреса почты, уникальность без учёта регистра |
| Reader | phone | Обязательное, до 30 символов, 10–15 цифр; допускаются начальный плюс, пробелы, скобки, дефисы |
| Reader | card | Вложенный билет обязателен; сохраняется в одной операции с читателем |
| LibraryCard | id | Положительный и уникальный; один билет не принадлежит нескольким читателям |
| LibraryCard | number | Обязательное, 3–32 символа; латинские буквы, цифры, дефисы; первый символ буква или цифра; уникальность без учёта регистра |
| LibraryCard | issuedAt | Обязательная реальная дата ГГГГ-ММ-ДД, не позже сегодняшнего дня |
| LibraryCard | expiresAt | Обязательная реальная дата ГГГГ-ММ-ДД, строго позже даты выдачи |

Проверка ISBN проверяет формат и уникальность; контрольная сумма ISBN не вычисляется. Просроченный билет разрешено сохранить, если срок окончания позже даты выдачи: такие читатели выделяются фильтром «Просрочен».

Уникальность учитывает логически удалённые записи. При редактировании запись исключается из сравнения по собственному id. Физическое удаление освобождает уникальное значение.

## Правила связей и сохранения

| Сценарий | Поведение |
|---|---|
| Смена издательства книги | Доступны авторы и жанры из его действующих книг; неподходящие выбранные значения удаляются из формы |
| У издательства нет действующих книг | Доступны все действующие авторы и жанры |
| Нужен новый автор или жанр для уже существующего издательства | Включить «Все авторы и жанры» и выбрать нужные записи |
| Удаление используемого издательства | Логическое и физическое удаление запрещено, выводится количество связанных книг |
| Физическое удаление используемого автора/жанра | Запрещено до изменения связей книг |
| Логическое удаление автора/жанра | Старые книги сохраняют название по ссылке; удалённая запись недоступна для выбора в новых/сохраняемых формах |
| Подсчёт препятствующих удалению связей | Учитываются все книги, включая логически удалённые |
| Пакетное удаление с недопустимой связью | Вся операция отклоняется, частичного удаления нет |
| Ошибка записи localStorage | Предыдущий снимок остаётся в памяти; ошибка показана, черновик формы сохранён |
| Неверная версия/повреждение | Исходный JSON сохраняется в library_catalog_v2_backup_..., загружается начальный набор и показывается баннер |
| Обнаружен старый ключ library_catalog_v1 | Старое значение сохраняется, создаётся каталог версии 2 и показывается сообщение |

Сохранённый пустой каталог не заменяется начальными данными. Несохранённые черновики не записываются в localStorage. Диалог выхода охватывает переходы внутри приложения и возврат браузером; полное обновление вкладки восстанавливает только сохранённые записи.
