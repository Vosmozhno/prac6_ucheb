# Учебный API для ПР4–ПР5

Основа — предоставленный mock-server.js, зависимости отсутствуют. Запуск из корня проекта:

    node api/mock-server.js --port 8080 --origin http://localhost:5555

По умолчанию сервер слушает 127.0.0.1; разрешённый источник — http://localhost:5555. Данные находятся в памяти и возвращаются к начальному набору при перезапуске. Служебный эндпоинт проверки — GET /api/__health.

## Дополнения к исходному серверу

1. POST/PUT /api/readers принимают вложенный card: number, issuedAt, expiresAt. При редактировании существующий билет обновляется, при создании назначается его id. Если card не передан при создании, формируется билет по умолчанию. Физическое удаление читателя удаляет его вложенный билет.
2. Сервер проверяет уникальность номера билета, его даты, ссылки authorIds/genreIds и ограничение количества экземпляров незакрытыми выдачами. ISBN сравнивается без дефисов и пробелов, почта — без учёта регистра.
3. В списках добавлен параметр filter, сохраняющий фильтры ПР3:

| Ресурс | Значение filter | Условие |
|---|---|---|
| authors | Страна | Точное совпадение country |
| publishers | Город | Точное совпадение city |
| genres | used / unused | Наличие / отсутствие связанных книг |
| readers | valid / expired | Действующий / истёкший билет |

4. Поиск читателя учитывает номер билета; sort=expiresAt,asc или desc сортирует по дате вложенного билета.
5. Удаление издательства со связанными книгами возвращает 409 с количеством связей. Для авторов и жанров такая проверка выполняется перед физическим удалением. Проверяется весь пакет до массового удаления; учитываются логически удалённые книги.
6. GET /api/publishers/:id/options возвращает компактные сведения для каскадных списков:

~~~json
{"hasBooks":true,"authorIds":[2],"genreIds":[1,3]}
~~~

Этот дополнительный эндпоинт вычисляет связи на сервере. Клиент не загружает все книги для построения выпадающих списков. Результат кэшируется до изменения каталога.

## Проверки сервера

    node --test api/mock-server.test.js

Тесты используют отдельный сервер на порту 8081: проверяют CORS/OPTIONS, полный CRUD пяти сущностей, вложенный билет, фильтры/сортировку/страницы, ответы 422 и 409 и возврат выданного экземпляра.

Остальные адреса, заголовок Bearer и правила ролей соответствуют исходному контракту. Дополнения выше необходимы для переноса возможностей ПР3 на API.

## Дополнения ПР5

- GET /readers и /loans, а также отдельные записи требуют аутентификации. Читатель видит только собственные записи; чужой id получает 403. Параметром readerId нельзя расширить доступ.
- POST /auth/register дополнительно проверяет специальный символ в пароле, имя и почту; роль из тела игнорируется. Создаются роль reader, связанный Reader и его LibraryCard.
- POST /loans/:id/renew — только reader для своей незакрытой выдачи, продление на 14 дней, не более одного раза. Ответ Loan дополнен renewedAt. Повторное продление или закрытая выдача возвращают 409.
- PATCH /users/:id/role — только admin; тело {"role":"reader|librarian|admin"}. Собственную роль менять нельзя, последний администратор защищён. При переводе в reader при необходимости создаётся читатель и билет.
- POST /__reset теперь также требует admin.
- GET /stats — только admin: books, readers, users, activeLoans, overdueLoans.
- Обобщённые PATCH/PUT/DELETE/restore и bulk-delete для loans закрыты: выдачи изменяются специальными операциями, сохраняющими количество экземпляров и проверку владельца.
- Для тестов поддерживается --refresh-ttl; по умолчанию refresh живёт неделю. --ttl 60 проверяет короткий access. Новая пара токенов имеет уникальные jti, прежний refresh аннулируется.
- Право определяется серверной учётной записью после проверки подписи access-токена. Параметр role из клиента и localStorage не участвует в проверке.

```bash
node --test api/mock-server.test.js api/auth.test.js
```

12 серверных проверок запускают отдельные процессы на 8081–8083. Файлы в Downloads не изменялись.
